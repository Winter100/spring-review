# 리뷰 이미지 자정 삭제 운영

- 단일 애플리케이션 인스턴스에서 매일 한국 시각 00:00과 기동 완료 시 처리합니다.
- 배포 전 `review-image-deletion-midnight.sql`을 PostgreSQL에 한 번 적용합니다. 적용 전에는 기존 대기 작업의 24시간 기준이 유지됩니다. 반복 적용하면 실패 재시도 시각도 초기화되므로 반복 실행하지 않습니다.
- 삭제 실행을 중지하려면 `storage.image-cleanup.enabled=false`로 설정합니다. 리뷰의 삭제 예약은 계속 저장됩니다.
- `DELETED`는 R2 객체 삭제 성공이 확인되었다는 뜻입니다. 업로드 이력의 `ATTACHED`는 과거 연결 이력으로 유지합니다.
- 과거 본문 이미지처럼 삭제 대상 업로드가 아직 `PENDING`이면 참조 검사 전에 `EXPIRED`로 닫습니다. 진행 중인 새 연결이 끝나기를 기다린 뒤 참조를 확인하므로 삭제 도중 새 리뷰에 연결되는 것을 막습니다. 이미 `ATTACHED`인 이력은 변경하지 않습니다.
- 실패 작업은 다음 한국 자정에 재시도합니다. `PENDING` 누적, 재시도 횟수와 참조 보류 로그를 확인합니다.
- 본문은 페이지 단위로 검사하므로 리뷰 수에 비례한 읽기 비용이 있습니다. 다중 인스턴스 운영 전에는 DB 작업 선점이 필요합니다.
- 실제 R2 확인은 전용 테스트 키를 업로드하고, 그 키만 대기 테이블에 등록해 삭제 가능 시각을 과거로 설정한 뒤 기동 보충 실행으로 확인합니다. R2 파일 부재와 DB의 `DELETED`, `deleted_at`을 함께 확인합니다. 다른 대기 작업이 없는 테스트 DB와 버킷을 사용합니다.
